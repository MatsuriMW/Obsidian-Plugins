## 要解决什么

在稿子库「Obsidian Vault」里写稿时，要在三个插件之间来回找：My Text Tools（文本处理）、第二大脑的写作模式（相关笔记 + Claudian）、追问成稿 qws-bridge（QWS / grill-me）。稿件台把它们按写作步骤收进一个入口：进写作模式，面板顶部就有四个下拉按钮。

## 写作流程

| 步骤 | 谁做 | 稿件台提供 |
|---|---|---|
| 1. 草稿 + 对话，写出脉络 | 对话 | **① 脉络**：grill-me 压测稿子 · 方向发散 |
| 2. 核实落实：查资料、补案例、解释概念 | AI 为主 | **② 落实**：填坑 · 概念锚点检索 · QWS 追问补料 |
| 3. 重新判断结构、整理大纲 | 自己 | 不做按钮（段落 → 列表用已有的 outline-block ⌘⌥L） |
| 4. AI 按段落扩写、润色、补充 | AI | **④ 扩写**：扩写 / 补充 · 正式化 · 文白交杂 |
| 5. 删、改、补 | 自己 | **⑤ 修整**：一键规范排版 · 列表块连成段落 |
| 6. 配图、发布 | mdflow | 不管 |

## 一、整体结构

- 新插件 `draft-desk`，单个 `main.js`、不编译，作者署名「马自立」（`sync.sh` 按这个识别自制插件）
- 开发目录在主库的 `.obsidian/plugins/draft-desk/`（`sync.sh` 从这里同步到本仓库），复制到稿子库启用；主库里不启用
- 读主库：主库路径从第二大脑设置的「外部素材库」里取，取不到才用稿件台自己的设置；用 Node `fs` 直接读文件
- 入口两个：
  1. 写作模式面板：第二大脑的 `RelatedView.renderTools()` 发现装了稿件台，就调它的 `renderButtons(el, getView)`，在「🤖 Claudian」后面接 `① 脉络 ▾` `② 落实 ▾` `④ 扩写 ▾` `⑤ 修整 ▾`。主库选题页上原有的「🎤 QWS 采访」「🔥 grill-me」不动
  2. 命令面板：每个操作一条命令（「稿件台：填坑」等），可绑快捷键
- 作用范围统一一条：**选中了就只处理选中部分，没选中就处理整篇**（属性区不动）

### 三种执行方式

| 方式 | 用在 | 体验 |
|---|---|---|
| MTT 快捷指令引擎（本地） | 规范排版 | 瞬间完成；直接改稿子（⌘Z 一步撤回） |
| 本机 `claude -p`（后台） | 方向发散、填坑、扩写、正式化、文白交杂、连成段落 | 状态栏「稿件台：正在…」，完成后预览或另存 |
| Claudian 对话 | grill-me、QWS 补料、概念锚点检索 | 侧栏新开一个对话标签，不打断正在进行的对话 |

调用 MTT：取 `app.plugins.plugins["my-text-tools"].batchManager.applyBatchOperationToText(op, text, "note")`，逐步执行，不走 MTT 的 `runBatchShortcut`（那条路径会直接 `setValue` 覆盖整篇）。

调用 `claude -p`：照 outline-block / journal-tidy，`--output-format json`，在临时目录里跑，带超时。

交给 Claudian：照 qws-bridge 的 `sendToClaudian` 复制一份。不直接调 qws-bridge，因为稿子库没装它，而且它的 `run()` 会把笔记正文搬进素材包，不适合稿子。

### 产出放哪

追问、发散、概念讨论的产出都算素材。按稿子库 CLAUDE.md，素材不放稿子库，统一放主库 `选题/_采访/<选题名>/`（和现在 QWS 的采访目录同一处；第二大脑的相关笔记本来就不索引这里）。选题名取稿子属性 `选题`，没有就用稿名。

## 二、每个操作

### ① 脉络

- **grill-me 压测稿子**（Claudian）：读稿子和对应风格提示词，一次一个问题、每题给推荐答案；盘问主张、受众、论证顺序、开头钩子、会被反驳的点、结尾落点。结论写成 `稿件压测-修改建议.md`，不动稿子
- **方向发散**（claude -p）：3–5 个不同写法（换角度 / 主张 / 结构 / 受众），每个附一句话主张和开头第一句。弹窗显示，同时存 `方向发散.md`，再跑追加一节带日期；弹窗里有「在主库打开」

### ② 落实

- **填坑**（claude -p，可联网、可读主库）：
  - 坑的写法固定为 `【坑：……】`
  - 每个坑单独查，并行最多 3 个，查完一个插一个；已有对应补料的坑跳过
  - Claude 返回结构化结果（内容 + 出处），插件排版后插在坑所在段落 / 列表块下面，坑在列表项里就按那一项的缩进插：

    ```
    > [!补料]- 坑：这里要一个印度的例子（2026-10-07）
    > - 查到的事实或案例 —— [来源](网址)
    > - 主库里的相关记录 —— [笔记名](obsidian://open?vault=马自立&file=…)
    ```

  - 坑标记保留，正文不改；查不到就写「没查到可靠来源」，不编
  - 主库笔记用 `obsidian://` 链接，因为稿子库里 `[[ ]]` 解析不到主库
- **概念锚点检索**（Claudian）：
  - 取概念：光标在 `[[链接]]` 上 → 用它；有选中 → 用选中文字；都没有 → 输入框
  - 找名字：主库里对应页面的主名称 + `aliases`；没有页面就只用这个词
  - 找提及：扫全主库，提到任何一个名字的地方都算（带不带 `[[ ]]` 都算），每处取所在列表块连同子块，或所在段落；跳过 `选题/_采访/`、`Templates/`
  - 材料包：概念页正文 → 日记（按日期）→ 其他笔记（按路径），上限 15 万字，存 `概念-<名称>.md`
  - 命中太多（比如超过 300 处）先提示确认
  - Claudian 结合当前稿子讨论：解释概念、在稿子里怎么用、往哪延伸；讨论完纪要写回同一文件夹
- **QWS 追问补料**（Claudian）：用 qws skill，从说得虚、缺例子、缺亲身经历的地方问起，稿子里写清楚的不问；公开表达素材线开启。结果写成 `稿件追问-补充素材.md`，每条注明可补到哪一段，不动稿子

### ④ 扩写

改写类共用一套落地方式：

- **选中**：弹预览（原文 / 结果对照）→ 替换 / 插在下面 / 复制 / 取消。替换是一次编辑，⌘Z 可撤回；等结果期间那段被改过就不替换，结果进剪贴板
- **整篇**：另存 `<稿名> v2.md`（已有就 v3…）。属性复制过去，改 `底稿: "[[原稿]]"`，加 `改写: <预设>`、`作者: AI 初稿`。新标签打开，然后后台跑稿子库的 `index-obsidian-vault.sh`
- 风格提示词从主库 `写作与创作/` 读，每次重新读
- 铁规矩：**只改正文句子**，`>` 标注、标题、表格、`【★】` `【坑】` 标记原样保留

三个预设：

- **扩写 / 补充**：按稿子属性 `形式` 选风格（口播稿 → 口播稿风格提示词；博客 / 长文 → 书面语风格提示词；其他 → 文稿风格提示词）。范围里的 `[!补料]` 当材料用，补料标注保留；不改主张，不加库里和补料里都没有的事实
- **正式化**：按书面语风格提示词
- **文白交杂**：白话为主，关键处用文言句式或四字格收束。主库还没有这份风格提示词，先起草 `写作与创作/文白交杂风格提示词.md`，审改后才是标准

「口语化」第一版不做，之后可以加成预设。

### ⑤ 修整

- **一键规范排版**（MTT）：中文和英文 / 数字之间加空格；中文语境里半角 `, ; : ? !` 和含中文的半角括号改全角，两头都是汉字（或在行尾）的半角句号改「。」；去行尾空格；合并连续空行。规则存成 MTT 快捷指令「稿件台 · 规范排版」，第一次运行时建好，可在 MTT 界面里增删。跑之前把 `[[链接]]`、嵌入、Markdown 链接、裸网址、行内代码、代码块换成占位符，跑完换回（防止 `[[A股]]` 变成 `[[A 股]]`）
- **列表块连成段落**（claude -p）：outline-block 的反方向。每个信息点都保留、顺序不变，可补连接词，不加新观点。落地方式同 ④

### 顺手改的

MTT 快捷指令「口播稿 → 提词版」：删整行的规则加上 `- 【坑` 开头的行；行内备注正则从 `【★[^】]*】` 扩成 `【(★|坑)[^】]*】`。`[!补料]` 以 `>` 开头，原规则已经会删。

## 三、出错怎么办

| 情况 | 处理 |
|---|---|
| 没装或没启用 My Text Tools | 规范排版提示「需要 My Text Tools」，其他功能照常 |
| 找不到 `claude` / 超时 / 返回错误 | 状态栏清掉，通知里给出原因（取前 300 字），稿子不动 |
| 等结果期间稿子被改了 | 选中模式：那段变了就不替换，结果进剪贴板；整篇另存不受影响 |
| 同一操作重复点 | 正在跑时再点一次 = 取消 |
| 填坑里某个坑失败 | 重试一次；还失败就在那个坑下面插一条「查证失败：原因」，其他坑照常 |
| Claudian 没装 / 正在输出 / 输入框找不到 | 提示词复制到剪贴板，并提示原因 |
| 主库路径取不到 | 需要主库的功能提示去设置里填，其他功能照常 |
| 另存时目标文件已存在 | 版本号往上加，不覆盖 |
| 索引脚本失败 | 只提示，不影响已经存好的文件 |

## 四、怎么验证

- 纯文本处理（作用范围、占位保护、补料插入位置、版本号）写成不依赖 Obsidian 的函数，用 `node` 跑断言，样本取真实稿子
- 涉及 Obsidian 和 AI 的部分在稿子库里实测，用 Obsidian CLI 的 `eval` 只读跑一遍，确认结果再写文件
- 每个子任务的完成标准写在对应的 Linear issue 里
